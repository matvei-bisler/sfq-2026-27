# SFQ 2026-27 — дашборд студенческих опросов

Streamlit-дашборд по трём волнам опроса учебного года:

| Волна | Опросник | С чем сравнивается |
|---|---|---|
| **Осень** — старт года | Стартовая анкета: ожидания, нагрузка, удержание, досуг | **Год к году** (осень 2026 ↔ осень 2027 …) |
| **Зима** — итоги 1 семестра | SFQ (как в 2025-26): удовлетворённость, NPS, CSI, преподаватели | **Зима ↔ весна** |
| **Весна** — итоги 2 семестра | SFQ | **Зима ↔ весна** |

## Запуск

```bash
pip install -r requirements.txt
streamlit run app.py
```

Для Streamlit Community Cloud: репозиторий → `app.py`, Python 3.11. Дашборд читает только `data/processed/`, `data/reference/contingent.csv` и `docs/`.

## Структура

```
app.py                      точка входа: выбор волны в сайдбаре
dashboard/common.py         фильтры, response rate, статистика, палитра
dashboard/autumn.py         осенняя анкета (10 вкладок, включая «Год к году»)
dashboard/sfq.py            зима/весна (вкладки SFQ 2025-26: NPS, CSI, преподаватели …)
process_autumn.py           выгрузка осени → data/processed/autumn_<год>.csv
process_sfq.py              выгрузки зимы/весны → data/processed/sfq_<волна>.csv
process_contingent.py       Контингент.xlsx → data/reference/contingent.csv
survey_utils.py             общие функции обработки (нормализация текста, реестр программ)
data/reference/programs_registry.csv   программа → школа, уровень
docs/codebook_autumn.md     кодбук осени (генерируется process_autumn.py)
docs/codebook_sfq.md        кодбук SFQ (шаблон по анкете 2025-26)
notebooks/clean_data.ipynb  исходный ноутбук предварительной очистки (заменён process_autumn.py)
```

## Обновление данных

**Осень.** Положите выгрузку Тестографа в `data/raw/autumn/autumn.csv` и запустите:

```bash
python process_autumn.py
```

Скрипт сопоставляет колонки по тексту вопроса (а не по номеру), поэтому переживёт перенумерацию и новые блоки курсов. Вопросы, которые не удалось сопоставить, выводятся как `WARNING` — добавьте их в `QUESTION_MAP`.

**Зима / весна.** Выгрузки по программам (по файлу на программу, xlsx или csv; имя файла = название программы, суффиксы «(2 сем)», «(зима)» отрезаются) — в `data/raw/winter/` или `data/raw/spring/`:

```bash
python process_sfq.py winter
python process_sfq.py spring
```

Переформулированные вопросы попадут в список unmapped-колонок — добавьте их в `COL_MAP`.

**Контингент** (для response rate и погрешности): `data/reference/Контингент.xlsx` в формате 2025-26, затем `python process_contingent.py`.

**Год к году.** Любой файл `data/processed/autumn_<ГГГГ-ГГ>.csv` (+ `_meta.json`) считается отдельным годом. В следующем году скопируйте сюда (или в репозиторий 2027-28) файлы осени 2026-27 — вкладка «Год к году» включится автоматически. Другой год можно собрать так: `python process_autumn.py --raw <выгрузка.csv> --year 2027-28`.

## Персональные данные

- В git **не попадают**: `data/raw/` (сырые выгрузки с контактами), `data/private/`, `Контингент.xlsx`.
- Вопрос о специальных условиях обещает ограниченный доступ, поэтому в публичном датасете только агрегированная категория `special_needs` (Нет / Да / Другое / Не ответил). Типы потребностей, описания и контакты — в `data/private/autumn_<год>_special_conditions.csv` для учебного отдела.
- В разбивках дашборда группы меньше порога (по умолчанию 5) скрываются.

## Реестр программ

`data/reference/programs_registry.csv` — школа и уровень для каждой программы. Строки с пометкой в колонке «Проверить» заполнены по догадке (новые программы 2026-27) — сверьте их.
